# OctoAcme — Project Kickoff Checklist

## Purpose
Provide a lightweight, repeatable checklist to ensure the right roles are engaged, key artifacts are in place, and ownership is clear before work begins on a new project or significant feature.

Use this checklist at project kickoff (after initiation, before planning sprint 1). See the [Roles and Personas](./octoacme-roles-and-personas.md) doc for full role descriptions.

---

## 1. Roles & Ownership

- [ ] **Project Manager (PM)** identified and confirmed
- [ ] **Product Manager (PdM)** identified and confirmed
- [ ] **Tech Lead / Developer representative** identified
- [ ] **QA/Testing** representative identified
- [ ] **UX Designer** engaged (if user-facing feature)
- [ ] **Data Analyst / Analytics Partner** engaged (if success metrics require instrumentation)
- [ ] **Release Engineer / DevOps** notified of upcoming release scope
- [ ] **Customer Support Lead** briefed on feature scope and expected customer impact
- [ ] **Key Stakeholders** identified and added to communication plan

---

## 2. Problem & Scope

- [ ] Problem statement written and agreed upon (see [Project Initiation Guide](./octoacme-project-initiation.md))
- [ ] Success metrics defined (quantitative where possible)
- [ ] Scope boundaries documented (in scope / out of scope)
- [ ] High-level timeline and milestone targets set
- [ ] Dependencies on other teams or systems identified

---

## 3. Artifacts & Tooling

- [ ] Project Charter / One-pager created and shared
- [ ] Project board set up (Backlog → Ready → In Progress → In Review → QA → Done)
- [ ] Repository and branching conventions documented
- [ ] CI pipeline configured (tests, linting, security scanning)
- [ ] Risk register initialized (see [Risk Management & Communication](./octoacme-risks-and-communication.md))
- [ ] Communication plan / stakeholder list documented

---

## 4. Planning Readiness

- [ ] Initial backlog created with epics or user stories
- [ ] Acceptance criteria written for top-priority items
- [ ] Definition of Done agreed upon by the team
- [ ] UX designs / wireframes available for sprint 1 items (if applicable)
- [ ] Analytics instrumentation requirements identified (if applicable)
- [ ] Estimates or t-shirt sizes assigned to backlog items
- [ ] Sprint 1 scope agreed upon

---

## 5. Release & Operations Readiness

- [ ] Release Engineer / DevOps aware of deployment requirements
- [ ] Rollback plan approach agreed upon (see [Release & Deployment Guide](./octoacme-release-and-deployment.md))
- [ ] Monitoring and alerting requirements identified
- [ ] Customer Support Lead has reviewed scope for support readiness (FAQs, runbooks)
- [ ] Security and privacy review triggered if required

---

## 6. Communication Cadence

- [ ] Daily standup time agreed upon and calendar invites sent
- [ ] Weekly delivery sync scheduled (PM + PdM + tech lead)
- [ ] Sprint/milestone demo cadence agreed upon
- [ ] Stakeholder update frequency agreed upon and owner assigned
- [ ] Escalation path documented (see [Risk Management & Communication](./octoacme-risks-and-communication.md))

---

## Handoff Summary

| Phase | Primary Owner | Supporting Roles |
|---|---|---|
| Initiation | Product Manager | Project Manager, Stakeholders |
| Planning | Project Manager | Product Manager, Developers, UX Designer, Data Analyst |
| Execution | Developers | Project Manager, QA/Testing, UX Designer |
| Release | Release Engineer | Project Manager, QA/Testing, Customer Support Lead |
| Retrospective | Project Manager | All roles |
